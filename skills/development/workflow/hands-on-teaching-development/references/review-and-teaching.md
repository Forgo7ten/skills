# 差异评估、教学自适应与持久化原则

## 一、DIFFERENT：先评价，再推荐，再由用户选择

1. 先读取 `review-diff.ts review` 首次输出中的 `diffs.userVsAgent` 等信息；只有截断时再打开对应完整报告。
2. 检查正确性和需求一致性；按需要分析性能、可维护性、清晰度、依赖、异常处理、安全边界和未来已准备 Commit 的影响。不要以字面不同判错。
3. 用简短对比告知用户：Agent 方案优点与局限、User 方案优点与局限、主要风险或权衡、**Agent 推荐哪种方案及具体原因**。
4. 单独列出「用户实现带来的新启发」（若没有则省略），判断是值得马上纳入还是仅作为候选优化。**候选建议未经用户确认不得自动加入产品范围**。
5. 如果 User 方案有明确 Bug、缺功能或违反已确认需求，指出具体位置与修复理由，不能把未修复的实现作为审查通过。用户可先修复重审，或选择 Agent 实现。
6. 用户明确选择 `user` 或 `agent` 后，运行 `review-diff.ts decide --choice user|agent --reason "..."` 记录结论（实质差异可附带可选的 `--recommend` 和 `--inspiration`；纯风格差异简短处理，不必机械填表）。
7. Review 结果、推荐理由、用户最终决定写 `development-log.md`；只有用户明确确认了可复用的长期工程偏好或产品要求才写入 `NOTES.md`。Review 的一次选型不等于长期偏好。
8. 对已经准备好后续 Commit 的批次，用户方案与后续步骤发生冲突时维持暂停与重排保护，不覆盖后续实现。

### 评估的输出格式（自然语言，无需冗长表格）

- **差异结论**：纯风格 / 等价实现 / 新增能力 / 遗漏 / Bug / 需进一步验证
- **Agent 优点与局限**：具体到本模块及未来维护
- **User 优点与局限**：具体到用户代码及风险
- **推荐方案与原因**：实质差异必须给出明确推荐，不无理由地让用户盲选
- **用户实现的新启发**（可选）：值得验证的候选优化，不是已确认需求
- **选择**：让用户决定 Agent / User，或要求先修复再 Review

纯格式或命名差异可以简短回答，不必强套四段优劣模板；但不能把“空白差异候选”当作语义安全的保证。

## 二、开发优先的自适应教学（不建学习档案）

- 教学粒度从实际编码进度、Review 结果、用户提出的明确疑问和用户自述已有知识来调整，不推测用户长期能力或给掌握度打分。
- 用户顺利完成且理解无需重复讲解：下一批次可以减少讲解和不必要的拆分。注意 Commit 仍要是易于理解、可验证的小功能。
- 用户多次在同一机制卡住或主动请求更细讲解：下一批次可以拆小步骤；当前批次**已经提交的 Commit 不自动拆分或重写**，可以增加文字讲解或在得到用户确认后重规划未教学的步骤。
- 如需跨会话记住短期讲解深度、重点或后续步骤拆分粒度，由 Agent 直接写在 `docs/teaching-state.md` 的「短期教学提示」自由 Markdown 区块中，注明观察依据即可，不需要脚本强制校验枚举。
- 相关事实可以简短记录在本步 `development-log.md`，不生成独立 `learning-records/`。
- 用户明确提出可长期适用的教学偏好时，由 Agent 直接更新 `docs/NOTES.md`（并随检查点提交）。单次卡顿或问题不会自动成为长期偏好。

## 三、文档职责与恢复顺序

- `MISSION.md`：一屏以内说明为什么做该产品、希望学会什么、成功标准和明确不做什么；变更目标要先获用户确认。
- `development-plan.md`：功能范围、技术方案、模块依赖、实施顺序和验收标准，不重复抄写 `MISSION.md` 或 `RESOURCES.md`。
- `RESOURCES.md`：具体 Example Project 路径、版本/SHA、可借鉴模块定位、价值与限制；不要复制全部源码。
- `NOTES.md`：由 Agent 直接维护的 Markdown 文档，记录当前有效的已确认需求、长期偏好、决策及纠偏（格式自由，冲突时明确废止旧条目）。
- `teaching-state.md`：JSON 区块由脚本维护双游标与当前批次；下方自由 Markdown 区块可由 Agent 记录短期教学提示。
- `development-log.md`：实际发生的开发、Review、修正与 Commit；可选记录与当前步骤有关的学习反馈，不维护能力档案。
- 恢复先运行 `progress.ts status`，然后直接阅读 `NOTES.md`、短 `MISSION.md` 及当前步骤对应的 `RESOURCES.md`；仅出现问题时展开开发计划、完整日志和 Git 历史。
