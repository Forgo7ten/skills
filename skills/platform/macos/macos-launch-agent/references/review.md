# 当前版本审查与验收记录

本文件描述当前实现、核对方式与验证边界。

## 核心结构

- 常规任务由 `install` 建立固定登录或日历配置。
- 扩展任务由 Agent 提供 XML，经转换器生成临时 plist，再由 `install-plist` 导入统一管理。
- 唯一安装事务 `commit_install()` 为两种入口统一执行归属校验、锁定、写入、注册、快照及失败回滚。
- 转换器禁止输出到自动加载目录，自定义任务只能通过托管安装器进入 LaunchAgents。
- 管理记录按当前字段结构严格校验必填字段、允许字段和快照原因；不自动接管未知文件。

## 多轮审查结果

1. **结构核对：** 两条配置创建路径只有一个托管事务，导出器没有安装参数；同名任务按 login/calendar/custom 隔离。
2. **旧行为清理：** 移除已停用 CLI 选项、自动识别共享 Label 的分支、固定模板对缺失 Umask 的宽容处理、元数据字段缺失的兜底，删除版本历史说明。
3. **记录约束：** 严格检查必填字段、未定义字段和快照原因；重建命令不能覆盖包含未定义字段的记录。
4. **错误与权限：** 修复审计发现的错误原因类型判断，父子管理目录均需 0700；损坏 JSON 仍可在用户明确确认后按当前配置重新创建记录。
5. **回归与发布：** 固定登录、日历、自定义导入、更新/回滚/卸载、转换器、故障注入及结构契约测试均纳入自动化套件。

6. **可观察性与命名：** 新建/更新输出按真实已登记状态提示，固定触发键可在 `install/list/status` 读取；英文语义名由 Agent 选择，脚本保留中文名 `job-<hash>` 兜底；统一使用 `local.my.agents.` 域。
7. **预览一致性：** 固定任务和自定义任务共用 `inspect_install_plan` 的只读磁盘预检，正式安装在锁内重新检查。覆盖冲突、孤立记录、未知来源 plist、哈希、模式及 `--replace`；预览和实际安装的触发/计划/工作目录/日志摘要由 `print_install_summary` 统一生成。预览不调用 launchctl，故不承诺注册成功。
8. **禁用诊断：** 自定义导入拒绝 `Disabled`（包括 false）；`print-disabled` 只解析明确匹配当前 Label 的持久禁用覆盖，不可解析时返回未知。明确禁用时注册前拒绝且不写盘；bootstrap 泛用 EIO 时做补充诊断，不将任意 EIO 直接归因于禁用；不自动 enable/disable。
9. **可用性与审计：** 逗号列表中的空项报告原始值和序号；XML 导出审计将未分配托管 Label 的 `label` 改为语义准确的 `source_label`，不会误报已托管。

10. **卸载与禁用覆盖：** 成功卸载仅删除托管 plist/JSON，系统的持久禁用覆盖可能保留。按 Label 提示而非误报任务文件残留；已禁用日历任务可以 `--replace --defer` 仅更新磁盘。`list` 短状态，`status` 详细指引；自定义源 Label 在预览与真实导入中对齐。
11. **调用场景：** `register` 的禁用指引标记为“当前命令必然注册”，只写盘参数只作为另一个 `install` 命令的建议，不可当成 `register` 参数；卸载禁用日历任务后，明确提示同名新任务 `--defer` 默认以外才只写盘。
12. **异常托管文件：** 固定模板差异输出多出/缺少/值不同的键名。新增显式 `drop-unrecognized --confirm-delete`，仅认可安全普通文件、有效管理记录、可解析且内部 Label 匹配的对象；未知运行态、未确认停止、来源不符拒绝删除，删除失败恢复管理记录且不自动加载被改动文件。
13. **故障注入：** 覆盖 bootout 部分成功、停止前失败、停止后外部再次写入、删除文件失败、符号链接、无记录、Label 不符和正常托管任务误用清理命令。

14. **漂移恢复建议：** 将模板可识别的磁盘哈希漂移与模板无法识别的修改分流；`status`、`install`/预览、`uninstall` 统一优先建议 `accept-plist`，仅确认丢弃时才提示 `drop-unrecognized`。不安全或无管理记录文件不提供自动清理出口；登录模板被改为 `RunAtLoad=false` 时指出应恢复有效模板再卸载，而不是修改自启语义键。

15. **缺失记录/文件恢复矩阵：** 有效记录+plist 缺失、损坏记录+plist 有效、损坏记录+plist 缺失、不可解析 plist、无记录同前缀 plist 分别生成可执行且有权限边界的指引；`list` 不再隐藏后者。损坏 JSON 且存在已加载同 Label 服务时，脚本不凭坏记录停服，要求人工确认；清理期间外部文件改变则中止。


16. **未管理路径分类与输出**：`lstat` 区分普通文件、目录、符号链接及其他条目，不跟随链接。普通未知 plist 一行摘要和统一恢复入口，非普通文件只显示异常类型而不提供误导性清理指引；`status` 独立显示详细恢复建议且统一分句，防止 `。；` 重复标点。

## 审查重点

1. 固定模板与扩展 XML 的职责清晰，自动加载目录只有托管管理器可以写入。
2. 不允许只凭 Label 相似就接管外部服务；无有效管理记录时拒绝修改和卸载。
3. `launchctl` 状态保守判定；无法确认已加载状态时阻止破坏性操作。
4. 文件/记录更新及回滚采取尽力恢复；恢复失败不得隐瞒可能仍在运行的任务。
5. 注册可能触发用户命令；只能经明确授权进行。
6. 通过静态契约、故障注入、XML 边界、权限和离线集成测试检验两种入口。

## 验证记录

本次修改后的工作目录通过 `python3 -m unittest discover -s tests -q` 运行 **278 项测试**，包括新增 17 项状态恢复矩阵回归，覆盖孤立记录、JSON 损坏、不可解析 plist、未管理文件、并发改动与运行态不确定；另新增 7 项未管理路径类型、简洁列表及提示标点回归测试。通过 Skill 元数据校验，Description 为 51 个字符。发布归档清除缓存文件，并从 ZIP 解压后重复相同测试；实际系统验证仍需要 macOS。

## 验证边界

离线自动化测试使用模拟 launchctl 与临时 HOME；只有真实 Mac 的 GUI 会话才能完成 plutil、launchctl、睡眠/唤醒和业务执行的端到端验收。代码测试通过并不保证任意扩展 XML 字段的系统行为。
